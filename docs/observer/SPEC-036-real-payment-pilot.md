# SPEC-036 支付宝单订单真实付款闭环

2026-10-18；Android #82、epay-go #24。承接 #8/#33/#42；本轮用户明确要求实际付款后 New API 余额增加。旧采样和合成充值结果保留，不升级为真实付款验收。

## 交付与启用分开

实现真实 `notification` 来源的受控结算能力，不复用 synthetic 身份、alias、永久合成claim或旧MD5回调。Android仍通过既有配对签名上报金额事件，网关事务记收入并安排既有持久商户回调；APK不确认订单、不持商户密钥。线上 New API 原配置保持不变。

当前没有实测收款模板。规则登记表默认空、规则必须明确启用并有私有样本核验引用；本批不虚构模板或启用生产采集。网关不提供公网试验登记或规则启用接口。真实采样范围、模板核验、下面的金额归属风险取舍及线上 New API 金额契约核对完成前，不登记线上试验、不催用户付款。

## 受控试验政策（Proposed，待启用前明确）

- 服务端登记现有 New API 创建的未付原订单，限定 environment、指定支付宝receiver、当前device/binding、EPay个人码通道、商户、精确分金额、规则版本、开始/截止。只支持支付宝，微信另验。截止显式传入、最多10分钟；原checkout有截止时不能晚于它，静态码没有截止时以本次服务端试验截止为准。登记不能续期或变更订单。
- 同receiver同时最多一笔有效试验；试验金额永久保留、不复用。该通道同额订单全部历史（含已付、过期、软删除）都算冲突，不以“只有一笔未付”消除歧义。不把此限制当可长期运营的生产政策。
- 首次认证接收事务内、持receiver锁，固定服务端候选快照；只允许登记后产生且收到的、未过截止的新鲜证据（最多迟到120秒、未来偏差最多2秒）。已恢复/不确定身份、未知规则、跨来源/绑定/金额、先前同额证据、暂停、失效规则/通道/商户、已结算或多候选均停止自动确认。
- 通知来源签名仅证明设备上报，不是支付宝交易验签。即使唯一同额也不能证明付款人和New API订单的平台归属；付款备注/聊天伪装风险必须由真实模板核验和明确试验范围控制，不能默认为无风险。
- 收入、订单已付、唯一消费、不可变决定、credited ACK在一个事务提交。失败全部回滚；同事件/封套重复只返回原结果。旧needs_review、旧采样、旧终局决定一律不升级，恢复不追溯入账。受控订单拒绝旧回调路径。
