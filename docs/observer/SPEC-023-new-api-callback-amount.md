# SPEC-023 New API 回调金额校验

2026-10-16；Android #10/#27/#29，epay-go #8/#9。New API 独立测试 checkout 固定 `633b4c5b190dc1af99a2814391354d86948e7943`；仅保存本地补丁/提交，不推第三方上游。该批不声称AVD完整充值已完成。

## 契约

- 保留既有 EPay 设置开关、签名验证和成功状态判断。验签成功后，把签名覆盖的原始 `money` 字符串作为必填参数交给充值事务；不得提供省略金额的兼容入口。
- 金额只接受1–15位ASCII整数，可有1–2位小数，总长至多18字节；不接受符号、空白、指数、非ASCII、缺省、零、负值和超过两位的小数。转为整数分精确比较，不按浮点容差比较；格式等价的10、10.0、10.00相等。
- 原单历史 `TopUp.Money` 是未必已舍入的float64。期望值严格复现既有下单参数 `strconv.FormatFloat(Money, 'f', 2, 64)`，再转整数分；不得改用另一种舍入导致历史单请求金额不一致。非有限、零、越界原金额失败关闭。不改数据库字段/迁移或定价公式。
- 事务锁定原充值单，核对 EPay provider 与金额后，才能返回重复成功或执行 pending→success 与额度增加。错金额即使订单已成功也返回失败，状态、余额不变。
- 增加的quota仍来自原 `TopUp.Amount` 和既有严格钱包边界函数；回调金额不得决定充值额度。保留原有实际支付方式更新语义、行锁、缓存同步和审计。
- 订阅支付和其他provider不在补丁范围。第三方AGPL源码/补丁保留原授权，不复制到MIT网关或Android实现。

## 验收

- NEW-AMOUNT-01：合法签名正确金额的GET/POST回调成功，重复/并发仅增加一次；校验发生在幂等返回之前。
- NEW-AMOUNT-02：合法签名错误金额、非法/缺省格式、未重签名篡改和错误签名均零增额；pending与success原状态分别保持。
- NEW-AMOUNT-03：历史未舍入Money复现请求精度（包括2.675→2.67），原Amount与money不同仍按原Amount增加quota。
- NEW-AMOUNT-04：真实SQLite/MySQL/PostgreSQL验证事务和幂等；保留既有quota上限、非EPay、非pending、缓存回归。记录版本和实际结果，缺失不得写通过。
