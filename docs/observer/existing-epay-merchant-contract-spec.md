# SPEC-046 既有EPay商户接口与通知准入分层

2026-10-19；Android #82 / epay-go #32，承接SPEC-036/041/043。用户明确只能修改epay-go和安卓观察器；New API的代码、配置、容器和数据库保持原样，SPEC-044线上替换方案撤回。

## 职责与版本

- 网关负责真实通知对应的原订单、精确金额、事务账务、持久商户回调及签名。商户使用既有EPay接口；接口核对不要求商户改内部事务实现。回调收到success仅表示ACK，不能证明实际增额。已知商户先ACK/内部事务风险保留为限制，不能声称网关已修复或保证商户入账。
- operator严格输入改为schema_version=2，保留模板/聊天/身份/金额四项事实，将newapi_contract_verified替换为merchant_callback_verified。后一事实只由网关operator核对既有商户EPay接口配置、验签/金额字段语义、回调成功/失败语义并记录私有证据；不能由成功构建、准备检查或采集器推定。实际投递和实际余额仍另验，未发生不写通过。任一事实缺失/0不登记。
- Android严格handoff改为schema_version=2，只携带原四项通知review及范围、证据引用，不含任何商户契约字段。APK无需了解商户内部入账实现；服务端已审核的商户事实不成为APK可自报字段。Android四项review任一缺失/0仍拒绝。
- 双方拒绝v1、重复/未知/混合版本及新旧商户字段；不自动转换旧review。不覆盖v1向量或旧私有记录，新v2向量两端逐字相同。旧工具和新工具不能互喂handoff；本批线上零rule/pilot，没有已登记试验需要迁移。后续登记仍须使用新operator和匹配的Android构建。
- 不改事件/签名/ACK wire、数据库schema、结算条件或公开API。固定官方来源、精确金额/绑定、新鲜窗口、同额全部历史、暂停、不可追溯、旧事件不升级、默认停止/Release隔离和审批引用保持。缺真实模板/聊天边界/身份或金额政策时继续拒绝启用，不因本次分层自动置review。
